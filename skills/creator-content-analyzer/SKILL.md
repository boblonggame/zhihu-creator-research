# 创作者内容观点分析

对标准 corpus 做可追溯的内容分析。统计脚本提供覆盖率、时间分布、类型分布和关键词证据；模型负责在不越过证据边界的前提下归纳观点。

## 运行条件

分析脚本需要 Python 3.9 或更高版本；定性归纳需要模型能够读取 UTF-8 JSON 和 Markdown。

## 可接受输入

优先接受符合 [corpus schema](references/corpus-schema.json) 的 JSON。也可接受用户明确提供且有合法使用权的公开内容文件；此时先转换为 schema，不直接在散乱原文上输出结论。

如果输入只是创作者主页 URL，先调用 `$zhihu-public-content-collector`。如果只有一篇内容，说明这只能做单篇解读，不能代表长期观点体系。

## 标准流程

### 1. 校验语料

运行：

```bash
python3 scripts/analyze_content.py corpus.json --keywords "关键词1,关键词2" --format json
```

脚本会做必要 schema 校验，给出类型、年份、字符量、覆盖率、标题/正文分列关键词频次和证据索引。任何校验错误都先修复或报告，不跳过。

先读 `meta.coverage`：

- `complete=false` 时，报告标题下必须写明不完整原因；
- 空语料不得生成人物或观点结论；
- 时间范围过窄时，把“长期观点”降级为“样本期内观察”；
- 重复、缺失 URL 或失败项会降低置信度。

### 2. 建立证据单元

完整阅读 [分析维度](references/analysis-dimensions.md)。对候选结论建立证据表，每条至少保留：

- 结论标签：`直接表述`、`跨内容归纳` 或 `证据不足`；
- 来源内容 ID、标题、日期、类型和 URL；
- 必要的短引或忠实转述；
- 支持、反例及适用时间范围。

不要用孤立高频词直接证明立场。频次只用于发现主题，观点需要语义和多篇来源互证。

### 3. 分维度归纳

按以下顺序分析：

1. 内容范围和阶段结构；
2. 反复出现的主题与知识框架；
3. 作者明确表达的观点、判断标准及其条件；
4. 论证方式、常用证据和反例处理；
5. 随时间出现的新增、弱化或反转；
6. 相互矛盾、无法核实和样本不足部分。

观点发生变化时，不用“前后矛盾”草率概括；先检查时间、话题对象和前提是否不同。

### 4. 区分三种结论

- `直接表述`：作者在来源中明确表达，允许短引并附链接。
- `跨内容归纳`：由多篇内容共同支持，但不是作者原话；必须写明这是归纳。
- `证据不足`：只有单篇、摘要、弱相关或相互冲突证据；保留问题，不强行下结论。

不得把“跨内容归纳”改写成作者原话。涉及事实主张时，说明这是作者观点还是已经由独立来源核验；本 Skill 默认只完成前者。

### 5. 渲染报告

使用 [报告模板](assets/report-template.md)。最终报告至少包含：

- 语料覆盖率、采集日期、时间跨度和失败项；
- 主题体系和长期观点；
- 重点领域与阶段变化；
- 论证方式与价值判断；
- 证据表、反例、证据不足项和局限性；
- 来源清单。

每个关键结论至少附一个可点击来源 URL；“长期”或“核心”结论原则上需要三个独立内容来源，达不到时降级措辞。

## 安全与解释边界

- 不推断政治倾向、宗教信仰、健康状况、性取向、精确住址等敏感属性。
- 不做人身诊断、去匿名化、私密关系猜测或基于语言风格的身份判断。
- 不大段复制原文；只保留分析所需短引，并优先使用忠实转述。
- 投资类创作者报告可加入“待核验事实、利益冲突和风险”章节，但不得输出买卖授权或自动修改用户交易规则。
- 明确区分平台互动量与观点正确性；高赞不等于事实已证实。

## 成功示例

- “用这份 corpus 总结作者的核心观点，并给每个判断附来源。”
- “比较他 2023 年和 2025 年对同一行业的看法是否变化。”

## 不应执行的示例

- “根据文章猜他的疾病、宗教和家庭住址。”
- “因为他高赞，所以把观点直接写进我的交易系统。”
- “只有一篇文章，也要断定他的长期价值观。”
