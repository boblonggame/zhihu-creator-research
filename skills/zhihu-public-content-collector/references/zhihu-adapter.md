# 知乎浏览器采集适配器

## 目标

从目标个人主页中枚举当前登录用户有权看到的回答、文章与想法。页面和内部请求都可能变化，先验证当次页面，再使用本参考。

## 优先路径

### 路径 A：浏览器页面和内容详情

1. 打开 `https://www.zhihu.com/people/<url_token>`。
2. 分别进入回答、文章、想法标签。常见路由是：
   - `/people/<url_token>/answers`
   - `/people/<url_token>/posts`
   - `/people/<url_token>/pins`
3. 逐页或逐段滚动，记录每张内容卡片的类型、标题、日期、互动数与详情链接。
4. 打开详情页读取正文。列表页只显示摘要时，标记为摘要或继续打开详情，不得当作完整正文。
5. 去重后再推进下一页；记录末页、重复游标或无新增内容等停止证据。

这是默认路径，适合任何能控制用户已登录浏览器的 Agent。

### 路径 B：页面自身的同源 JSON

只有当浏览器工具允许在已打开的知乎页面中安全读取页面自身的同源响应时才使用。历史上常见的版本敏感端点包括：

```text
/api/v4/members/<url_token>/answers?limit=20&offset=<n>
/api/v4/members/<url_token>/articles?limit=20&offset=<n>
/api/v4/members/<url_token>/pins?limit=20&offset=<n>
```

每页单独请求并验证：HTTP 状态、`data` 是否为数组、分页字段是否存在、下一页是否推进。字段可能需要 `include=` 参数，且名称会变化：

- 回答标题通常来自 `question.title`，正文通常来自 `content`；
- 文章标题通常来自 `title`，正文可能来自 `content` 或详情页；
- 想法可能使用 `content`、`excerpt` 或嵌套对象；
- 日期可能是 Unix 秒时间戳，也可能是 ISO 字符串；
- 互动字段可能是 `voteup_count`、`comment_count`、`favorite_count`。

不得从浏览器提取 Cookie 后转给 `curl` 或脚本；不得把成功过一次的端点承诺为长期稳定 API。

## 官方知乎工具的边界

若环境提供官方知乎 CLI 或连接器，先查询 capabilities。当前常见能力偏向搜索、热榜、知乎直答及当前账号自己的内容；如果不能按任意目标作者枚举全部内容，就切换浏览器路径，不要把搜索结果拼成“全量”。

## 原始批次建议格式

规整脚本接受平台原始对象，但采集阶段优先补充这些稳定字段：

```json
{
  "id": "123",
  "type": "answer",
  "title": "示例问题",
  "content": "<p>公开正文</p>",
  "created_time": 1735689600,
  "url": "https://www.zhihu.com/question/1/answer/123",
  "voteup_count": 10,
  "comment_count": 2,
  "favorite_count": 1
}
```

`type` 可以在分批保存时显式补充。若无法取得正文，仍记录来源 URL，并在失败清单中写明“仅列表摘要 / 详情不可达”。

## 覆盖率判定

- `complete=true`：所有请求类型均到达可验证末页，且没有未解释失败。
- `complete=false`：用户主动设置条数/时间上限、平台总数不可核对、存在失败项、限流或权限中断。
- 页面展示总数与逐页去重数不一致时，不强行凑数；记录两者和可能原因。

## 安全停止语句

- 未登录：“当前页面需要登录。请在这个浏览器窗口中自行完成登录；不要把密码或 Cookie 发给我。”
- 验证码：“知乎要求人工验证，我已暂停；完成验证后可从当前页继续。”
- 限流：“平台返回限流信号，我已停止继续请求并保留当前覆盖率。”
- 结构变化：“当前页面字段与适配器不一致，不能保证完整性；需要先更新适配器再继续。”
